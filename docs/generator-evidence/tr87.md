# TR87 full-generator characterization

Measured 2026-09-18. TR87 has exactly **six** shipped levels (`levels`,
`third_party/arc3_games/tr87.py:472-877`). This is a one-reference-per-tier
calibration: every tolerance is explicit and must not be read as a population
confidence interval.

## Complete mechanic inventory

- The player has four real display actions: cycle the selected glyph digit
  down/up modulo seven and move the cursor backward/forward cyclically
  (`Tr87.step`, lines 974-1022). Cycling preserves the A/B/C family. Selection
  and cycling each cost one budget unit; only a cycle action runs the solved
  check.
- Rule connectors define ordered left/right glyph sequences. Rules and lower
  rows are sorted by `(y, x)`. The solved check greedily takes the first rule
  matching the current source prefix. Multi-symbol left and right sides occur
  in official tiers 2, 3, 5, and 6. The engine compares only the demanded
  target prefix; extra target glyphs would be ignored (`bsqsshqpox`, lines
  1044-1105). Generated profiles retain the exact official row lengths, so the
  permissive trailing-target quirk is not used to reduce difficulty.
- Direct translation is used in tiers 1-3. Tier 4 enables
  `double_translation`: an A->B rule must compose with a B->C rule. The latent
  paired-marker extension in `lonhgifaes` is audited, but no official level
  places any `tjaqvwdgkxe` marker, so it is not labeled an official mechanic
  and generated full tiers do not invent it.
- Tier 5 enables `alter_rules`: the cursor has `2 * rule_count` groups and a
  cycle edits every glyph on one complete rule side by the same modular
  offset. Target cells are fixed.
- Tier 6 enables `alter_rules`, `tree_translation`, and
  `double_translation`. Tree translation replaces each first-stage RHS symbol
  using the first rule with that symbol at `lhs[0]`. The source has three
  first-stage symbols, each producing two target symbols through three
  second-stage rules.
- Material engine limitation: `tree_translation` is an `if` branch and
  `double_translation` is its `elif` (`tr87.py:1065-1095`). Thus tier 6 carries
  the official double flag, but tree translation shadows the double branch.
  Requiring simultaneous double-branch use would be impossible in the native
  engine; the generated certificate records `tree_shadows_double=true`.
- Entry applies deterministic cosmetic rotations and deterministic, native
  context-index scrambling (`on_set_level`, lines 910-969). Budgets are 128
  for indices 0-4 and 256 for index 5. Budget zero loses.
- A successful cycle starts an automatic seven-color transition per matched
  segment, displays rule halos, then advances naturally to the next level
  (`step`, lines 974-993). Certificates call the real native action API and let
  this animation/advance run; they do not force transitions.

Tiers 1-4 were solved by exact A*. Tier 5's 14 actions come from exhaustive

## Generator and proof design

- Default `DIFFICULTIES` is `(1, 2, 3, 4, 5, 6)`. Every tier independently
  samples glyph relations, outputs, source composition/order, rule order,
  within-region placement, and row alignment. Counts and arity composition are
  fixed because those are the measured official structures; geometry and
  assignments are not copied. Direct tiers deliberately sample arbitrary
  same-family clean target glyphs as the originals do, rather than storing an
  already-solved row that collapses action difficulty.
- Tiers 4-6 construct the actual official mechanic composition. Tier 5's
  generated witness rules solve a newly sampled mixed-arity grammar; tier 6's
  witness rules form a new A->B->C tree. Generator v3 procedurally chooses the
  repeated head and child, requires one repeated-child plus two mixed-child
  first-stage expansions, and guarantees that all three secondary rules occur
  in the winning parse. Generated tiers 5-6 additionally apply independently
  sampled pre-scramble offsets to every displayed rule side while retaining a
  generated satisfying-rule certificate; combined with native context
  scrambling this prevents a fixed action script across examples.
- Verification occurs at `training_context_index == difficulty - 1`, with the
  native budget and fixed context scramble. The constructive witness is
  replayed through `Tr87.perform_action`; acceptance requires a real win and
  one natural level completion. Every action is one of 1..4 with null x/y.
- `teacher_search` covers all official tiers and replans from a live prefix.
  Direct target modes use exact A*. Direct editable rules use exhaustive
  grammar assignments. Generated editable/tree levels use a native-replayed
  satisfying-rule certificate, recorded as non-optimal. TR87 exposes no undo
  action; recovery coverage
  therefore replans and replays from a live partial-action prefix.
- Geometry identity hashes tile/connector anchors canonically under translation
  and all eight D4 transforms. Gameplay identity normalizes per-family cyclic
  digit relabeling while retaining meaningful rule order. Split selection is
  `hash % 3` over the geometry identity, never inferred from seed ranges.
  Official identities are derived from clean shipped levels; a candidate is
  rejected if either canonical geometry or gameplay equals an official row.
  Bank/full-game builders also reject duplicate identities.
- Candidate drawing, split mismatch, structural/proof gates, and official-copy
  checks are bounded by `attempts`. Rejection counts are stored in
  `generation_exclusions`. A cutoff or exhaustion is never reported as proof
  of impossibility.
- Native tile and backing rectangles are validated using their complete sprite
  widths/heights. Generated content is kept inside horizontal render bounds
  `[2, 62]` on the 64x64 frame, leaving a visible two-column gutter instead of
  allowing a 7x7 backing to sit flush against the camera crop. The same gate is
  recomputed by `validate_full_standard`; checking anchor coordinates alone is
  insufficient.
- `generate_game` derives stable BLAKE2 child seeds from source ID, game seed,
  ordinal, and tier. `build_game` accepts exactly six ordered, same-split,
  distinct, revalidated specs, preventing native context shifts. Validation
  recomputes identities/partition and structural metrics, then replays the
  stored route in the real intended context to recompute density, budget, and
  mechanic-use evidence. For tier 6 that evidence is derived from the actual
  successful native grammar trace and admission requires both mixed-child and
  repeated-child expansions; an installed but unused rule cannot satisfy the
  gate. `build_game` additionally replays the complete six generated tiers
  sequentially. Explicit reduced generation is smoke-only and `build_game`
  rejects it.
